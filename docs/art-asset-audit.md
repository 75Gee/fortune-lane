# 美术素材调研与生图清单

盘点日期：2026-09-11。依据当前源码、素材引用、图片尺寸及现有界面效果图。

后续定稿：用户选择更简单的卡通方案，机会为黄底白边问号，命运为粉底白边感叹号。用户提供的两宫格图片已裁切、去除外部白底并接入；抽卡、揭晓、牌库和动态共用符号，命运UI同步改粉色。原先旅行徽章、邮戳式复杂卡背方向取消。其余素材仍为候选建议，尚未接入。

## 结论与优先级

最值得补齐的是卡牌的专属美术、少量关键事件插画和棋盘中心的装饰地图。城市、医院、补给站、路障、炸弹及六枚棋子已有实体模型；这些模型可以直接生成界面缩略图。程序绘制的文字、骰点、接地投影与操作图标是有意保留的轻量实现。

## 统一视觉要求

以[当前游戏界面](./previews/game-contact-shadows.png)和[现有模型](../apps/web/public/assets/models/preview.png)为参考：柔和微缩桌游、圆润轮廓、哑光材质、低饱和薄荷绿与奶油白，少量暖金和雾粉点缀。主体在小尺寸下仍可识别，避免密集微小细节。

统一身份：**机会黄色问号、命运粉色感叹号、道具补给薄荷绿**。命运卡UI此前与地标颜色不一致，已随新卡背接入调整。后续图片采用简约卡通、大轮廓，避免为了装饰增加徽章、邮戳等额外识别元素。

各类素材的光照要求不同：

- UI独立插画可以有轻微自身明暗，使用柔和一致的光向，避免长投影和大范围外发光。
- 地图、纸张、海面等用于3D表面的颜色贴图应使用均匀光照，不画投影、镜头透视或高光，以免与场景光照冲突。
- 所有中文、英文、金额、骰点、卡牌编号、城市名称和功能性图标由代码排版。生图只交付画面，不把游戏规则烘焙进图片。
- 独立主体四周保留约12%安全边距。透明素材需要真实Alpha；生成器不支持透明时可交纯白底，后续抠图。不要把灰白棋盘格画成背景。
- 每个素材单独生成一张，保持相同画风、相机角度和主体占比。卡背外轮廓使用完整矩形，圆角由界面裁切。

## 第一批可直接使用的生图提示词

### 1–2. 机会、命运卡背 — 已完成

采用用户实际使用的提示词：

> 白底两宫格图，左侧是机会卡卡背（黄色卡背白色边框，中间是一个问号），右侧是命运卡卡背（粉红色卡背白色边框，中间是一个感叹号）。整体呈大富翁游戏卡通简约风格。

成品及裁切说明见 [卡背素材目录](../apps/web/public/assets/cards/README.md)。无需重新生成。

### 3. 收入主题 — `event-income`

> 为世界旅行微缩桌游绘制一枚可复用的事件主题插画：一个打开的小旅行钱包，几枚无文字、无数字的金币，一张空白奖励票券，表现收到分红、奖金或旅途礼金。正方形构图，主体居中，四周12%留白。柔和圆润的哑光玩具质感，三分之四视角，奶油白、低饱和薄荷绿、少量暖金；清晰的大轮廓，细节适量，温暖轻盈。透明背景，无大面积投影，无场景底座。不要任何文字、数字、货币符号、品牌、水印，不要写实金属强反光，不要散落大量小物件，不要画出棋盘格透明背景。

### 4. 通行许可主题 — `event-permit`

> 与收入主题保持相同的哑光微缩玩具画风、三分之四视角和主体占比。画一张奶油白旅行通行卡，搭配一个打开的小门和一枚薄荷绿色圆形印章，表达旅途恢复畅通、可以继续出发。通行卡完全没有文字或编号，印章不带文字。正方形，主体居中，四周12%留白；薄荷绿、奶油白、少量暖金，柔和自身明暗，干净透明背景。不要警徽、红色警报、复杂机场场景、人物、文字、数字、Logo、水印，不要长投影，不要绘制棋盘格背景。

### 5. 棋盘中心地图 — `board-center-map`

> 为世界旅行主题桌游制作一张正方形的装饰地图底图。严格正上方平视，无透视。整体是低对比度、低饱和的薄荷灰绿色，参考底色#8faf9e；以仅略深或略浅的颜色描绘概括的世界大陆剪影、少量弧形旅行航线、很淡的邮戳轮廓和指南针装饰。图形平面化、细节克制，呈细腻纸面印刷感，与奶油白、薄荷绿微缩建筑模型协调。中央约40%的区域保持低细节，边缘平缓过渡到统一底色。它是背景装饰，不是可游玩的路线图。不要任何文字、字母、城市名称、数字、边框、棋盘格、站点编号、建筑、玩家棋子、骰子、投影、立体高光或黑色粗线。

以下9类覆盖现有64张卡，无需64张独立美术。第一批已包含收入、通行许可，两张定稿后再补剩余7类。

| 素材ID | 主体构思 | 对应内容 |
| --- | --- | --- |
| `event-income` | 钱包、少量无字金币、空白奖励票 | 分红、奖金、返还、礼金、业主扶持 |
| `event-expense` | 小钱包、空白账单、少量金币 | 罚款、检查费、保险、托运、资产登记 |
| `event-travel` | 小行李箱、指南针、车票形状 | 起点、城市邀约、机场、公用事业、前进 |
| `event-detour` | 弯曲道路、小路牌、行李箱 | 后退、临时改道；也可用于被路障截停后的说明 |
| `event-detention` | 小型看守建筑、空白手续文件 | 手续有误、接受调查；避免暴力和惊悚元素 |
| `event-permit` | 通行卡、小门、绿色印章 | 免费出狱或出院的保留卡 |
| `event-hospital` | 奶油白小医院、薄荷绿医疗标记 | 探望朋友、住院结果；用文案明确探访与住院的区别 |

这些插画采用第一批主题图的通用风格要求，都是1:1、1024×1024母版、主体居中。医院与看守建筑可先由现有3D模型导出，用同样的构图处理，进一步减少生图数量。

## 更适合复用、加工或建模的部分

### 地产与棋子缩略图

地产详情和竞拍目前以图标、表格和金额为主，可以补一条矮幅地标头图。优先从棋盘现有城市模型按统一相机角度、统一光照离线导出，运行时加载小图，不在每个弹窗再启动一个3D画布。

六枚棋子已有独立SVG头像和3D模型。若想让头像与棋盘更一致，也可从3D模型导出透明缩略图；保留外层玩家颜色环由代码绘制。无需重新设计六个主体。

### 两个事件地标

用户已选择用问号与感叹号作为卡背核心识别，棋盘中的现有立体符号与之对应，保留这一简约方向。先前建议的咨询亭、邮筒及复杂徽章不再作为本轮目标，也不需要额外生成模型参考图。

### 四张道具图

现有 `items/*.png` 已用于道具包、目录、行动揭晓和动态记录，均为611×611、无Alpha的白底PNG，约308–356 KiB/张。当前不缺主题美术，可以优先抠底、清理白边，再导出带Alpha的WebP和小尺寸版本。保留原图，不需要用户重新生成。

其画风是较鲜明的卡通描边，和棋盘哑光模型存在媒介差异；可通过统一留白、卡面容器与颜色协调。只有需要整套重做时才把它纳入新的事件画风。

## 接入时的性能与清晰度要求

- 母版留存，运行时根据实际显示尺寸导出2倍像素版本；独立事件图常用256或512像素，卡背可用400×560，中心地图先以1024×1024接入，是否升到2048看清晰度需要。
- UI插画优先WebP，透明主体保留Alpha；不要把源图大小等同于运行时大小。建议目标：事件图约30–100 KiB，卡背约60–150 KiB，中心图约150–300 KiB；这些是制作预算，压缩后以边缘质量和实物观感为准。
- 所有卡牌使用统一的素材映射和卡面组件，按语义选择插画；牌堆颜色、标题、规则、金额、玩家信息和操作按钮仍由代码统一输出。
- 首屏只加载首页需要的图；事件图在需要展示时加载，避免一次下载全套高分辨率母版。
- 材质贴图集中用在少数大平面，复用纹理和材质。给每栋楼新增独立贴图会影响现有合批，不能直接假定贴图越多模型越省性能。
- 不生成整张游戏UI、整张棋盘格子、含中文说明的完整卡牌、整盘骰点或转盘数字。保留规则信息的清晰度和可更新性。
- 接地阴影已经是单次合批绘制的程序渐变，不再需要阴影图片、动画精灵序列或实时AO效果。当前爆炸也已有轻量几何粒子，暂不需要专门生图。

这份清单中的插画与造型方向是设计建议，接入时还需调整对应组件；把图片放入资源目录本身不会改变当前界面。
