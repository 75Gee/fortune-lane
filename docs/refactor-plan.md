# 游戏重构实施计划

更新日期：2026-09-14

状态：A～D 已完成本轮编码，类型检查和生产构建通过；桌面及窄屏的本地预览已做交互核对。未编写、修改或运行测试，未完成多人真实对局验收。

## 本轮落地

- `GameView` 与协议投影隔离内部牌堆；选牌携带决策编号。共享报价、赎回价、出售建筑所得及结构化错误码已接入前后端。
- 普通结果改为紧凑播报，完整动态可回看；移除结果阅读倒计时与双阅读控制。旁观决策主动查看，本人必需决策自动呈现。
- 资产列表可直接管理，详情在原面板内返回并恢复滚动与焦点；道具包只列持有道具。首页、等候室、对局和战报已精简文案。
- 引擎按规则职责拆分，阶段转换集中清理待处理状态，关键动画事件约束必需载荷。新增原子命令 `ROLL_AGAIN`，保留道具额度和连续对子规则。
- 房间阶段从游戏状态派生，连接状态以房间成员为准，所有结算共用提交入口。请求、保存记录、事件缓冲已拆开。
- 棋盘 React 外壳、场景控制器、输入和镜头计算已拆开；事件播放与场景使用同一共享帧循环。3D 模型及美术资产未修改。

后续观察：真实多人局的操作节奏、长时间断线恢复、低性能手机的帧率。账号、商城、存档和新玩法仍不在本轮范围。

## 1. 总体目标

将游戏推进到正式面向玩家的产品状态：玩家能清楚看到当前局面、理解下一步、连续完成操作，开发者也能在明确的规则和模块边界内扩展玩法。

目前最影响体验的问题，是不重要的信息占据视觉核心，以及玩家需要额外管理弹窗、阅读进度和面板切换。文案与样式调整应当围绕这些问题展开。

保留现有基础：

- 现有 3D 模型和美术资产。
- 独立的游戏规则包、服务端权威结算、完整状态快照同步。
- 已有命令编号去重、重连恢复、整局统计。
- 独立表现状态、共享 RAF、按需渲染、隐藏暂停与减少动态效果支持。
- 2～6 人好友对局、当前地图与经济规则。

重构按可独立审查的批次进行，逐步收拢职责。账号、商城、排行榜、多地图、跨重启存档等新产品能力不属于本次范围。

## 2. 已确定的玩家界面方向

### 信息层级

主界面的视觉顺序为：当前局面 → 当前行动 → 费用和结果 → 辅助资料。

- 棋盘和当前玩家的真实决策保持主要位置。
- 同一个行动只保留一个主要状态说明，合并顶部、底部与悬浮提示中的重复内容。
- 普通结算使用紧凑反馈，完整内容进入历史；提示可被回看，不能只依靠瞬间消失的文字传达关键结果。
- 正常状态不常驻连接实现、记录清理机制、功能介绍等说明。
- 倒计时清楚可见；超时后果在相关决策附近说明，避免多个区域反复强调。

### 决策、动画与结果阅读

- 当前玩家需要购买、升级、出价、选择目标或地产时，提供明确的决策界面。
- 获得道具、普通资金变化、进入医院等已经结算的结果，改为非阻断反馈，后续操作不再等待固定的 8～14 秒阅读时间。
- 掷骰、移动、陷阱触发等必要动画保留先后关系；解锁决策仍须遵循棋盘表现已到达相应落点这一条件。
- 去掉主界面中两套独立的阅读进度管理，减少“停留阅读、继续、返回当前回合、下一条”等并存的控制。
- 历史承担完整阅读与复盘；正在查看历史时保留阅读位置，新的行动通过轻量提示告知。
- 重连、切回前台和跳过表现后，直接恢复最新局面，清理已经失效的展示和决策。

### 旁观体验

- 其他玩家行动时默认保持棋盘可见，通过紧凑信息展示动作和结果。
- 旁观者不再默认面对遮住棋盘的购买界面或无法点击的三张卡背。
- 自己需要参与竞拍等决策时，及时提供操作入口；所有人仍可获知公开结果。
- 查看资产、规则或历史时，普通旁观信息不抢焦点。
- 减少打断应体现在默认行为中，避免通过不断增加设置让玩家自己修正体验。

### 资产与地点操作

- 资产列表、地产详情和管理操作形成连续路径。
- 从列表进入详情，返回时保留资产持有人、列表位置和原上下文。
- 常用出售建筑、抵押、赎回操作靠近对应资产，直接展示金额与不可用原因。
- 筹款沿用并改善现有列表快捷操作，缺口与可筹金额清楚可见。
- 棋盘选中地点后的摘要与详情减少重复层级，结合点击选中、拖动相机的区别整理入口。
- 普通购买、升级和出价在一个明确的决策界面完成；破产、投降保留必要确认。
- 投降入口集中在对局菜单及确有需要的场景，不再通过通用弹窗注入到地产详情、道具和旁观卡牌等界面。

### 道具

- 道具包优先展示玩家已经持有的道具。
- 选中后直接呈现目标、骰点或放置地点，再执行使用。
- 保留影响本次决定的后果，例如路障拦截、炸弹送医和行动额度限制。
- 未持有道具与完整规则归入牌库/道具说明，避免与当前可操作内容同等突出。
- 使用结果不再接上另一个需要等待或继续阅读的普通弹窗。

## 3. 文案与样式

### 文案准则

采用稳定的玩家语言，围绕“现在发生什么、我能做什么、操作会带来什么后果”表达。

| 当前问题 | 目标表达 |
| --- | --- |
| 等候室出现“新增开罗、香港” | 规则描述当前玩法，移除版本更新口吻 |
| 重返区域常驻清理机制和设备入口说明 | 正常状态简洁；操作相关说明放到对应入口，异常状态再说明原因 |
| “等待购买决定”等内部阶段标签 | 按身份呈现具体行动，例如“是否购买香港？”或“小满正在考虑购买” |
| “本回合道具额度已用完” | “本回合已使用过道具” |
| 泛化的“行动进行中” | 能确定动作时显示正在掷骰、移动或等待谁出价 |
| 一个界面混用加盖、升级及其他近义词 | 购买、升级、抵押、赎回、游览费等操作和金额术语保持一致 |

首页与战报保留旅行主题和适度趣味；付款、欠款、超时、破产、投降的动作与后果保持准确。

### 视觉准则

- 延续现有绿色桌游气质，统一颜色、字号、间距、圆角、边框和按钮层级。
- 当前主要行动突出，辅助资料和低频操作降低视觉重量。
- 城市、金额、行动标题与说明文字形成清晰层次，减少低对比度小字堆叠。
- 购买、升级、竞拍统一信息顺序：对象 → 费用与收益 → 操作后结果 → 行动按钮。
- 保留影响决策的价格、余额、竞拍底价及后果；完整租金表和详细规则按需展开。
- 首页突出继续对局、创建、加入；等候室突出邀请、准备和开局条件；战报突出结果、个人表现和继续游玩的入口。
- 手机布局保证操作触达、文字可读和弹层滚动，不以不断叠加说明挤压棋盘。

## 4. 技术重构范围

### 公开协议与共享规则

重构前 `ServerState.game` 直接使用完整 `GameState`，会下发牌堆顺序和待选卡牌身份。本轮已改为独立 `GameView`，由协议投影按字段构造。

- 建立独立的玩家可见快照，按允许的字段构造输出。
- 牌堆顺序和未揭晓卡牌留在服务端；前端选牌使用槽位、稳定的决策标识等公开数据。
- 牌库继续展示静态卡牌说明与公开数量，避免依赖内部牌堆数组。
- 保留当前已有的公开玩家信息、历史、统计和按玩家隐藏竞拍报价的行为。
- 本地演示也通过同一公开视图交给 UI，防止演示与真实联机的数据契约分叉。
- 租金、资产管理条件、赎回价、出售建筑所得、出狱费用等由共享规则提供，前端展示和服务端校验使用同一依据。
- 查询接口返回可用性、费用和拒绝原因；服务端始终重新校验客户端命令。

主要涉及：`packages/game/src/types.ts`、`economy.ts`、`items.ts`，`packages/protocol/src/index.ts`，`apps/server/src/rooms.ts` 及前端数据消费者。

### 错误、连接和房间协调

- 将错误码、可重试性和显示文案分开，移除通过文案包含“超时”“连接”来判断行为的逻辑。
- 明确操作已拒绝和结果尚未确认的区别，同一命令重试沿用同一编号。
- 将请求发送/重试、会话恢复、事件缓冲、保存房间记录分开管理。
- 明确房间编排、游戏领域数据和玩家连接状态的归属，减少两份状态手工同步。
- 玩家命令与超时代操作共用结果提交逻辑，集中更新房间阶段、截止时间和广播结果；保留竞拍独立截止时间及现有计时规则。
- 明确重开、重连、房间切换与命令去重的生命周期，不把内存缓存扩展成未经要求的新持久化系统。

主要涉及：`apps/web/src/socket/useGameConnection.ts`、`apps/server/src/rooms.ts`、`apps/server/src/index.ts`、`packages/protocol/src/index.ts`。

### 行动状态机

- 按移动、地产、卡牌、竞拍、转盘、债务划分规则职责。
- 将阶段及其必需数据绑定，明确合法转换与中断路径。
- 集中管理行动完成和后续恢复，特别是“自选骰子 → 抽卡/竞拍/欠款 → 结算 → 恢复原行动”。
- 入狱、住院、破产、投降、换人、结束对局采用明确的清理与恢复规则。
- 按事件类型约束必要载荷，减少通过大量可选字段表达所有事件。
- 保留目前可注入随机源和时间、复制状态后结算、拒绝命令不提交变化的基础。

主要涉及：`packages/game/src/engine.ts`、`types.ts` 及相关规则模块。

### 表现与页面职责

- 统一事件进度、动画完成和跳过的语义，区分必要动画与可随时阅读的普通结果。
- 集中协调当前决策、旁观反馈和主动打开的资料界面，减少分散的布尔状态与相互关闭逻辑。
- 将 `GamePage` 中行动栏、资产面板、路线视图、资料与弹层协调拆到明确的组件边界。
- 将 `BoardScene` 的场景生命周期、状态投影、相机/输入控制和资源释放分离，保留模型工厂与现有调度能力。
- 根据实际职责整理 `global.css` 与 `gameplay.css` 的覆盖关系，随组件迁移收拢样式。
- 六人规模下的少量数组扫描不是首要重构目标；性能改动以实际瓶颈为依据。

## 5. 操作简化的规则边界

`WAITING_FOR_END_TURN` 仍允许使用道具、抵押、赎回和出售建筑。简化展示不能意外剥夺这些机会。

- 对子追加时可将“继续行动 → 掷骰子”整理为一个明确的“再掷一次”，执行前保留道具和资产操作机会；引擎校验与超时入口必须一致。
- 所有落点结算后无条件自动换人，不属于已确定的方案。
- 三选一卡、手动启动转盘主要提供仪式感；是否取消留待后续评估，首批保留现有规则与随机结算方式。
- 转盘后的地产选择、道具目标、出价等真实决策继续由玩家明确完成。
- 更少的旁观弹窗不改变公开信息范围、密封竞拍或结算结果。

## 6. 编码批次

| 批次 | 工作内容 | 完成标准 |
| --- | --- | --- |
| A：边界与规则基础 | 玩家可见快照；共享费用与操作查询；结构化错误 | 不下发牌堆顺序/待选真实卡牌；预览和联机使用相同 UI 数据契约；重试行为不依赖中文文案 |
| B：优先减少游玩负担 | 非决策结果非阻断；旁观默认轻量；合并重复提示与阅读控制；移除通用弹窗的投降入口 | 玩家只在真正需要选择时面对主要决策界面；普通结果可回看；动画、下一步和倒计时衔接正确 |
| C：连续操作与页面成品化 | 资产列表/详情连续导航；道具包精简；首页、等候室、对局、战报文案；共享样式与组件收拢 | 查看下一项资产无需重开面板；道具使用路径直接；费用和后果清楚；桌面与手机信息层级一致 |
| D：内部职责收拢 | 行动状态机；会话/计时统一提交；连接模块拆分；场景生命周期拆分；追加行动入口简化 | 复杂行动有明确恢复出口；玩家命令和自动命令遵循一致规则；页面与场景职责清楚 |

A～D 的本轮代码已落地，具体变更见文首。

## 7. 验收与工作约束

以下保留设计验收标准；已做的静态检查与本地预览不等于所有多人场景已完成验收：

- 需要自己决策时，能看到具体对象、费用、余额/结果和一个明确的主要行动。
- 旁观他人抽卡、购买、道具使用时，棋盘与主动查阅内容保持可用；自己参与竞拍时操作及时可达。
- 普通结果不会因固定阅读时间阻塞下一次真实操作；完整原因和金额仍能从历史找到。
- 查看资产、返回列表、查看下一项连续完成；筹款缺口随操作更新。
- 重连与切回页面恢复最新状态，不补播过期决策；重复命令不重复扣款或累计统计。
- 自选骰子、对子追加、住院/监狱、卡牌选地、竞拍、欠款与投降维持原有规则。
- 主页面统一术语和样式，清理已被新流程替代的说明与控件。

遵循用户提供的 AGENTS.md：默认不编写、修改或运行测试；只有用户明确要求或项目级指令强制要求时才执行。编码后的基础检查使用静态审查、TypeScript 类型检查和生产构建，并如实报告覆盖范围。界面走查使用本地演示，不能据此声称多人实局或真实设备性能已经验证。

代码设计与实现由主代理负责；需要子代理时仅安排独立只读检索和证据整理，使用 `default`、`fork_turns="none"`，并明确禁止继续派生。
